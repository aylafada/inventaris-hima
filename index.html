JOBSHEET 01 · MINGGU 2

HTML5 Semantic Skeleton

Jadi kerangka untuk semua jobsheet berikutnya: di-styling (J2), dibuat responsif (J3), diberi interaksi (J5), lalu diisi data dinamis (J6 dan seterusnya).

Tujuan Pembelajaran

  • Menyusun halaman Beranda, Daftar Buku, dan Form Tambah Buku dengan tag HTML5 semantic yang valid.
  • Membuat tabel (table/thead/tbody) dan form (form/label/input/select/button) dengan struktur yang benar.
  • Menamai atribut id dan name secara konsisten supaya form tidak perlu dirombak saat dipakai PHP.

Konsep kunci

Tag semantic itu apa?

Tag yang namanya menjelaskan fungsinya. <header>, <nav>, <main>, <section>, <article>, dan <footer> memberi tahu browser, mesin pencari, dan screen reader bagian mana berisi apa. Tampilannya bisa sama persis dengan <div>, tapi maknanya jelas.

Peran tiap tag

header = kepala halaman (judul + menu). nav = kumpulan link navigasi. main = isi utama, cukup satu per halaman. section = kelompok isi bertema, biasanya diawali judul. article = konten yang berdiri sendiri, misalnya satu kartu statistik. footer = penutup halaman.

Struktur tabel

thead menampung baris judul kolom (th), tbody menampung baris data (td). Pemisahan ini penting: di Jobsheet 5 filter hanya menyaring baris tbody, dan di Jobsheet 6 JavaScript mengisi tbody dari JSON.

id vs name pada form

id dipakai untuk menghubungkan label, untuk CSS, dan untuk JavaScript. name adalah kunci data saat form dikirim ke server, misalnya $_POST['judul'] di PHP. Keduanya perlu ada dan konsisten.

Aturan penamaan

Pakai huruf kecil dan snake_case: no_anggota, bukan NoAnggota atau No Anggota. Ini syarat penilaian karena nama field yang sama dipakai ulang sampai jobsheet PHP.

Validasi HTML

Semua tag harus tertutup dan bersarang dengan benar. Cek hasilnya di validator.w3.org sebelum dikumpulkan.

JOBSHEET 02 · MINGGU 3

CSS3 Styling Dasar

Tidak mengubah struktur HTML Jobsheet 1, hanya menambah assets/css/style.css. File ini disempurnakan di Jobsheet 3.

Tujuan Pembelajaran

  • Menerapkan box model dan selector CSS untuk menata Beranda, Daftar Buku, dan Form Tambah Buku.
  • Memakai Flexbox untuk navbar dan CSS Grid untuk kartu statistik.
  • Membuat tampilan konsisten antar halaman dengan selector yang bisa dipakai ulang.

Konsep kunci

Menghubungkan CSS

Tulis <link rel="stylesheet" href="..."> di <head>. Path relatif mengikuti kedalaman folder: dari index.html memakai assets/css/style.css, dari buku/list.html memakai ../assets/css/style.css. Kalau path salah, CSS tidak terbaca dan halaman tampil polos tanpa pesan error.

Box model

Setiap elemen adalah kotak berlapis: content, lalu padding, border, dan margin di luarnya. box-sizing: border-box membuat width sudah termasuk padding dan border, sehingga hitungan lebar lebih mudah ditebak.

Selector dan specificity

Selector bisa berupa tag (table), class (.card), id (#judul), atau pseudo (:hover, :nth-child(even)). Kalau dua aturan bentrok, yang lebih spesifik menang (inline > id > class > tag). Kalau sama kuat, yang ditulis belakangan menang.

Flexbox (satu dimensi)

Mengatur item dalam satu baris atau kolom. justify-content mengatur sumbu utama, align-items sumbu silang, gap jarak antar item. Pas untuk navbar.

Grid (dua dimensi)

Mengatur baris dan kolom sekaligus. grid-template-columns: repeat(3, 1fr) membuat tiga kolom sama lebar. Pas untuk kartu statistik.

CSS variable

Nilai yang dipakai berulang, seperti warna, ditulis sekali di :root (--navy) dan dipanggil dengan var(--navy). Ganti tema cukup di satu tempat.

Dipakai ulang tanpa class baru

Selector berbasis tag semantic dan nth-child membuat halaman Anggota otomatis tampil sama dengan halaman Buku, karena struktur HTML-nya sama.

JOBSHEET 03 · MINGGU 4

Responsive Design (CSS murni)

Menyempurnakan style.css Jobsheet 2. Tidak ada halaman baru. Hamburger versi CSS ini diganti toggle JavaScript di Jobsheet 5.

Tujuan Pembelajaran

  • Menambahkan meta viewport dan memahami cara kerja media query.
  • Membuat navbar hamburger memakai checkbox hack, tabel yang bisa digeser, dan grid yang berubah kolom.
  • Menguji tampilan di tiga breakpoint memakai DevTools.

Konsep kunci

Meta viewport

Tanpa <meta name="viewport" ...>, HP menampilkan halaman seolah layar desktop lalu mengecilkannya. Dengan tag ini lebar halaman mengikuti lebar layar sebenarnya. Wajib ada di semua halaman.

Media query

@media (max-width: 480px) { ... } berarti aturan di dalamnya hanya berlaku saat lebar layar 480px atau kurang. Breakpoint yang dipakai: mobile ≤480px, tablet sekitar 768px, desktop ≥1024px.

Mobile-first vs desktop-first

Mobile-first: tulis gaya dasar untuk HP, lalu tambah layout lebih lebar dengan min-width. Desktop-first: tulis gaya desktop, lalu kecilkan dengan max-width. Jobsheet menganjurkan mobile-first. Pilih satu pola dan pakai konsisten di seluruh halaman.

Checkbox hack

Trik tanpa JavaScript: label mengontrol checkbox tersembunyi, dan selector :checked ~ nav menampilkan menu saat kotak dicentang. Kekurangannya, kurang ramah keyboard dan screen reader, makanya diganti JS di Jobsheet 5.

Tabel responsif

Bungkus tabel dengan div ber-overflow-x: auto. Di layar sempit tabel bisa digeser ke samping, halaman tidak ikut melebar.

Menguji

Buka DevTools (F12), aktifkan mode device (Ctrl+Shift+M), lalu coba lebar 480, 768, dan 1024. Pastikan tidak ada elemen terpotong atau muncul scroll horizontal pada halaman.

Kode dan penjelasan

Meta viewport
html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
  • width=device-widthLebar halaman mengikuti lebar layar perangkat.
  • initial-scale=1.0Zoom awal 100%, tidak diperbesar atau diperkecil otomatis.
  • LetaknyaDi dalam <head>, di semua halaman.

  • header nav { display: none }Di layar kecil, menu disembunyikan lebih dulu.
  • .nav-toggle:checked ~ navSelector ~ memilih nav yang berada sesudah checkbox dalam induk yang sama. Saat dicentang, nav ditampilkan lagi.

JOBSHEET 03 · VERSI BOOTSTRAP

Responsive Design dengan Bootstrap 5

Alternatif Jobsheet 3 dengan framework. Halaman dan fungsinya sama, tapi tata letak dibangun dari class Bootstrap, bukan CSS tulisan sendiri.

Tujuan Pembelajaran

  • Memasang Bootstrap 5 lewat CDN dan memakai komponen serta utility class-nya.
  • Menyusun tata letak dengan grid 12 kolom (row dan col-*).
  • Menimpa warna bawaan Bootstrap dengan CSS sendiri agar sesuai warna brand.

Konsep kunci

Framework CSS

Kumpulan class siap pakai. Kita menulis nama class di HTML, bukan aturan CSS dari nol. Hasilnya style.css menyusut dari sekitar 245 baris menjadi sekitar 15 baris.

CDN

Bootstrap dimuat dari internet lewat dua baris: file CSS di <head> dan file JS (bundle) sebelum </body>. JS dibutuhkan agar navbar bisa dibuka-tutup. Konsekuensinya, butuh koneksi internet.

Grid 12 kolom

Susunannya .container lalu .row lalu .col-*. col-12 col-md-4 artinya satu baris penuh di HP, dan sepertiga lebar mulai layar ≥768px. Breakpoint: sm 576, md 768, lg 992, xl 1200.

Komponen bawaan

Navbar (navbar navbar-expand-lg, navbar-toggler, collapse navbar-collapse), kartu (card), tabel (table table-striped table-hover), form (form-control, form-label), tombol (btn btn-warning btn-sm).

Utility class

Class kecil dengan satu tugas: jarak (mb-3, my-4, p-3), teks (fw-bold, fs-2, text-center, text-secondary), bayangan (shadow-sm).

Menimpa gaya Bootstrap

CSS sendiri harus dimuat setelah file Bootstrap supaya menang. Warna brand bukan bagian tema bawaan, jadi ditulis lewat CSS sendiri atau mengganti variabel --bs-*. Pastikan style.css benar-benar terbaca; kalau path salah, Bootstrap tetap jalan tapi warna brand hilang.

JOBSHEET 05 · MINGGU 6

JavaScript DOM dan Event

Menghidupkan halaman Jobsheet 1 sampai 3 sesuai wireframe Jobsheet 4, murni di sisi browser. Belum terhubung ke server atau database.

Tujuan Pembelajaran

  • Memilih elemen DOM dan memasang event listener.
  • Membuat dan menghapus elemen lewat JavaScript untuk menampilkan pesan error validasi.
  • Membuat filter tabel real-time dan konfirmasi hapus tanpa memuat ulang halaman.

Konsep kunci

DOM

Representasi halaman sebagai pohon objek. JavaScript bisa membaca dan mengubah pohon ini sehingga tampilan berubah tanpa reload.

Memilih elemen

getElementById("id") mengambil satu elemen lewat id. querySelector("css selector") mengambil elemen pertama yang cocok. querySelectorAll(...) mengambil semuanya sebagai daftar yang bisa di-forEach. Kalau elemen tidak ada, hasilnya null, jadi selalu cek sebelum dipakai.

Event

Hal yang terjadi di halaman: click, keyup, submit, DOMContentLoaded. elemen.addEventListener("click", fungsi) menjalankan fungsi saat event itu terjadi. Fungsinya menerima objek event, dan e.preventDefault() membatalkan aksi bawaan seperti submit form.

Mengubah elemen

classList.toggle("nav-open") menambah atau mencabut class. textContent mengubah teks. style.display menyembunyikan atau menampilkan. createElement, insertAdjacentElement, dan .remove() membuat dan menghapus elemen.

Pola init

Setiap fitur dibungkus fungsi initXxx() dan semuanya dipanggil di DOMContentLoaded. Satu app.js bisa dipakai semua halaman karena tiap fungsi berhenti (return) bila elemen yang dicarinya tidak ada di halaman itu.

Validasi client-side

Memberi umpan balik cepat tanpa menunggu server. Tapi bisa dilewati (misalnya JS dimatikan), jadi validasi di server tetap wajib, dibahas di Jobsheet 7.

confirm()

Menampilkan dialog OK/Batal. Mengembalikan true kalau pengguna memilih OK. Dipakai sebelum aksi yang tidak bisa dibatalkan.

Kode dan penjelasan

Validasi form dan pesan error inline
js
function tampilkanError(input, pesan) {
    hapusError(input);
    const span = document.createElement("span");
    span.className = "error";
    span.textContent = pesan;
    input.insertAdjacentElement("afterend", span);
}

function hapusError(input) {
    const next = input.nextElementSibling;
    if (next && next.classList.contains("error")) {
        next.remove();
    }
}

function initValidasiForm() {
    const form = document.getElementById("form-tambah");
    if (!form) return;

    form.addEventListener("submit", function (e) {
        let valid = true;

        const tahun = form.querySelector("[name='tahun']");
        if (tahun) {
            const nilai = parseInt(tahun.value, 10);
            if (isNaN(nilai) || nilai < 1900 || nilai > 2026) {
                tampilkanError(tahun, "Tahun harus di antara 1900-2026.");
                valid = false;
            } else {
                hapusError(tahun);
            }
        }

        if (!valid) {
            e.preventDefault();
        }
    });
}
  • createElement + className + textContentMembuat <span class="error"> baru berisi pesan. Elemen ini belum tampil sebelum dimasukkan ke halaman.
  • insertAdjacentElement("afterend", span)Menyisipkan elemen tepat setelah input, tanpa mengubah elemen lain.
  • hapusError(input) dipanggil duluMencegah pesan error menumpuk kalau pengguna submit berkali-kali.
  • nextElementSiblingElemen tepat sesudah input. Dicek apakah itu span error sebelum dihapus.
  • parseInt(tahun.value, 10)Nilai input selalu string. parseInt mengubahnya jadi angka (basis 10) supaya bisa dibandingkan.
  • isNaN(...) || nilai < 1900 ...Gagal kalau bukan angka atau di luar rentang.
  • let valid = trueBendera penanda. Setiap field yang gagal mengubahnya jadi false, lalu dicek sekali di akhir.
  • e.preventDefault()Membatalkan pengiriman form kalau ada field yang tidak valid.

function initTableFilter() {
    const input = document.getElementById("search-input");
    const table = document.querySelector("table");
    if (!input || !table) return;

    input.addEventListener("keyup", function () {
        const keyword = input.value.toLowerCase();
        const rows = table.querySelectorAll("tbody tr");

        rows.forEach(function (row) {
            const teks = row.textContent.toLowerCase();
            row.style.display = teks.includes(keyword) ? "" : "none";
        });
    });
}

  • row.textContentSeluruh teks dalam satu baris, jadi pencarian mencakup semua kolom.
  • teks.includes(keyword) ? "" : "none"Kalau cocok, display dikosongkan (kembali ke bawaan). Kalau tidak, baris disembunyikan.

JOBSHEET 06 · MINGGU 7

Fetch API dan JSON

Mensimulasikan pengambilan data dari server memakai file JSON statis. Pola fetch yang sama dipakai lagi untuk memanggil endpoint PHP di jobsheet berikutnya.

Tujuan Pembelajaran

  • Menulis data dalam format JSON dan membacanya dengan fetch.
  • Menampilkan data secara dinamis dengan async/await, lengkap dengan loading indicator dan penanganan error.
  • Memahami event delegation untuk elemen yang dibuat setelah halaman dimuat.

Konsep kunci

JSON

Format teks untuk menyimpan data. Array ditulis [ ... ], objek { "kunci": nilai }. Kunci dan teks wajib memakai kutip ganda. Tidak boleh ada koma di elemen terakhir dan tidak boleh ada komentar.

Fetch dan Promise

fetch(url) mengembalikan Promise, yaitu janji hasil yang baru ada nanti. Bisa disambung dengan .then(), atau ditulis lebih mudah dibaca dengan async/await. Kata await hanya boleh dipakai di dalam fungsi async.

Dua langkah

await fetch(...) menghasilkan objek Response. Lalu await res.json() mengubah isinya menjadi array atau objek JavaScript. Keduanya Promise, jadi masing-masing perlu await.

Cek res.ok

fetch tidak otomatis gagal untuk 404 atau 500; itu tetap dianggap respons berhasil diterima. Karena itu cek res.ok, dan lempar error sendiri kalau false.

try / catch / finally

try menjalankan proses, catch menangani error, finally selalu dijalankan. Cocok untuk menyembunyikan loading, baik proses berhasil maupun gagal.

Loading indicator

Tampilkan sebelum fetch, sembunyikan di finally. setTimeout dibungkus Promise (await new Promise(r => setTimeout(r, 600))) untuk mensimulasikan jaringan lambat agar loading sempat terlihat.

Event delegation

Tombol Hapus kini dibuat setelah halaman selesai dimuat, sehingga listener yang dipasang saat DOMContentLoaded tidak menjangkaunya. Solusinya, pasang satu listener di document, lalu cek e.target.closest(".btn-hapus").

Path dan server

Path di fetch dihitung dari halaman HTML, bukan dari file JS. Dari buku/list.html, ../data/buku.json berarti naik satu folder lalu masuk data/. Halaman harus dibuka lewat server (Live Server atau php -S localhost:8000). Lewat file://, fetch diblokir browser.

Jebakan yang sering terjadi

Loading berputar terus: <script src="...buku.js"> belum dipasang di HTML, atau id elemen di JS berbeda dengan di HTML. Pesan 404: folder atau nama file JSON salah, atau server membuka folder yang keliru. Setelah dipasang online: server harus mengizinkan file .json disajikan.

Catatan keamanan

innerHTML dengan data dari luar bisa disusupi skrip (XSS). Untuk data JSON statis milik sendiri aman, tapi untuk data yang berasal dari pengguna, lebih aman memakai textContent. Topik ini dibahas lebih jauh di jobsheet keamanan.

buku.js: fetch dengan async/await
js
async function muatDaftarBuku() {
    const tbody = document.getElementById("tabel-buku");
    const error = document.getElementById("error-buku");
    const loading = document.getElementById("loading-buku");
    if (!tbody) return;

    loading.style.display = "block";
    tbody.innerHTML = "";
    error.textContent = "";

    try {
        await new Promise((resolve) => setTimeout(resolve, 600));

        const res = await fetch("../data/buku.json");
        if (!res.ok) {
            throw new Error("Gagal mengambil data (status " + res.status + ")");
        }
        const daftarBuku = await res.json();

        daftarBuku.forEach(function (buku) {
            const tr = document.createElement("tr");
            tr.innerHTML =
                '<td>' + buku.judul + '</td>' +
                '<td>' + buku.pengarang + '</td>' +
                '<td>' + buku.tahun + '</td>' +
                '<td>' + buku.stok + '</td>' +
                '<td>' +
                '<button type="button">Edit</button> ' +
                '<button type="button" class="btn-hapus">Hapus</button>' +
                '</td>';
            tbody.appendChild(tr);
        });
    } catch (err) {
        error.textContent = "Gagal memuat data: " + err.message;
    } finally {
        loading.style.display = "none";
    }
}

document.addEventListener("DOMContentLoaded", muatDaftarBuku);
  • async functionMenandai fungsi yang boleh memakai await di dalamnya.
  • Tiga getElementByIdMengambil tbody, wadah error, dan loading. Id-nya harus cocok dengan HTML.
  • loading.style.display = "block"Menampilkan loading sebelum proses dimulai. Isi tabel dan pesan error lama dibersihkan.
  • await new Promise(... setTimeout ...)Jeda buatan 600 ms agar loading terlihat. Dihapus saat memakai server sungguhan.
  • await fetch("../data/buku.json")Meminta file JSON. Path dihitung dari buku/list.html.
  • if (!res.ok) throw new Error(...)Status 404 atau 500 diubah jadi error, sehingga masuk ke blok catch.
  • await res.json()Mengubah isi file menjadi array JavaScript.
  • forEach + createElement + appendChildUntuk tiap buku dibuat satu <tr>, diisi <td>, lalu ditambahkan ke tbody.
  • catch (err)Menampilkan pesan error di halaman, bukan hanya di console.
  • finallySelalu jalan: loading disembunyikan baik data berhasil maupun gagal.
  • addEventListener("DOMContentLoaded", ...)Fungsi dijalankan otomatis begitu halaman siap.

Event delegation untuk tombol Hapus
js
function initHapusConfirm() {
    document.addEventListener("click", function (e) {
        const btn = e.target.closest(".btn-hapus");
        if (!btn) return;

        const row = btn.closest("tr");
        const nama = row ? row.querySelector("td")?.textContent : "data ini";

    });
}

  • ?.textContentOptional chaining: kalau hasil sebelumnya null, tidak error, hanya menghasilkan undefined.
  • Kenapa berubah dari J5?Di J5 tombol sudah ada saat halaman dimuat. Di J6 baris dibuat oleh fetch, jadi listener per tombol akan terlewat.
